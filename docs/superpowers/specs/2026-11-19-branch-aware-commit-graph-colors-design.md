# 分支语义提交图配色设计

## 目标

- 提交图颜色表达分支归属，而不是提交哈希。
- 同一分支的 first-parent 历史保持稳定颜色。
- Merge 的额外父边使用对应父分支或父提交颜色。
- 搜索、路径过滤和分批加载时，分支颜色仍由完整分支列表驱动。
- 颜色在相同分支集合下跨刷新和重新打开仓库保持一致。

## 非目标

- 不修改后端 Git 日志数据。
- 不改变提交图 lane 的拓扑计算规则。
- 不要求每个提交只属于一个分支；共享提交按优先级选择一个主颜色。
- 不为 Tag 单独分配分支调色板颜色。

## 分支颜色分配

- 颜色源为分支名，不使用提交哈希作为分支主色。
- 优先级固定为：
  1. 当前 `HEAD` 本地分支。
  2. 普通本地分支，按分支名稳定排序。
  3. 远程分支，按分支名稳定排序。
- 本地分支和远程分支使用不同颜色身份。
- 调色板保持 8 色。
- 每个分支从分支名哈希得到首选颜色。
- 首选颜色已占用时，按调色板顺序寻找下一个未使用颜色。
- 超过 8 个同时存在的分支后允许重复颜色。
- 分支集合不变时，颜色分配结果稳定。
- 当前颜色分配基于完整的 `useBranches()` 数据，不依赖当前日志页是否包含分支 tip。

## 同提交多分支

- 一个提交同时对应多个本地或远程分支时，只选择优先级最高的一个主颜色。
- 当前 `HEAD` 分支优先于普通本地分支。
- 普通本地分支优先于远程分支。
- 同优先级分支按分支名稳定排序决定。
- 其他分支仍保留各自 ref chip，但不会同时改变提交节点颜色。

## First-parent 传播

- 分支 tip 首先使用自身分支颜色。
- 提交的 primary parent 沿 first-parent 继承当前提交颜色。
- 如果父提交本身是分支 tip，则父提交节点使用自己的分支颜色。
- 如果一个提交有多个子提交，优先由日志顺序中较新的第一条 first-parent 传播确定颜色。
- 没有分支归属且无法继承颜色的提交使用基于 OID 的稳定回退色。
- Tag-only 提交不占用分支颜色，优先继承所在分支；无归属时使用回退色。

## Merge 边

- Merge 提交的额外父边优先使用对应父分支颜色。
- 父分支已删除或不可见时，使用该父提交的稳定回退色。
- 主父边继续使用当前提交已经传播的主颜色。
- Merge 边仍保持较低透明度，以区别于主线。

## Lane 颜色

- `GraphRow` 同时保存每条 lane 的 OID 和颜色。
- 穿过当前行的 lane 使用该 lane 已经传播的颜色，不再通过 OID 临时哈希。
- lane 被回收并分配给其他提交后，使用新提交已经确定的颜色。
- 提交节点、主线、贯穿线和 Merge 边都读取同一份传播色数据。

## 组件边界

- `src/lib/graph.ts` 负责：
  - 分支颜色分配。
  - 颜色碰撞处理。
  - 分支 tip 种子。
  - first-parent 和 Merge 颜色传播。
  - lane 与边构建。
- `src/features/history/HistoryView.tsx` 读取完整分支列表并传给 `buildGraph`。
- `src/features/history/HistoryDetails.tsx` 只负责按 `GraphRow` 数据绘制。
- 后端 `CommitDto`、`BranchDto` 和日志查询接口无需修改。

## 回退策略

- 日志查询不包含分支 tip 时，使用完整分支列表中的 tip OID 作为颜色种子。
- 分支已被删除或提交没有可达分支归属时，使用 OID 哈希回退色。
- 分支数量超过调色板容量时允许重复，不生成无限新颜色。
- 无分支、无父提交或空日志不能导致除零、越界或 lane 颜色缺失。

## 测试

### 纯函数

- 线性分支的所有 first-parent 提交保持同色。
- 当前分支优先于普通本地分支。
- 普通本地分支优先于远程分支。
- 分支名哈希碰撞时选择下一个未使用颜色。
- 超过 8 个分支后颜色循环。
- 分支 tip 不在当前日志页时仍能作为颜色种子。
- Merge 额外父边使用父分支色。
- 已删除父分支使用稳定回退色。
- Tag-only 提交使用所属分支色或稳定回退色。
- 贯穿多行的 lane 颜色保持一致。

### 组件与视觉

- `GraphCell` 使用 `GraphRow` 提供的 lane 颜色，不重新哈希 OID。
- 更新历史页视觉基线。
- E2E 验证提交图仍然可滚动、没有横向溢出。

## 验收标准

- 同一分支的主线颜色保持连续。
- Merge 的两条父路径可以通过颜色区分。
- 同一提交对应多分支时颜色选择符合优先级。
- 搜索和过滤场景下分支颜色保持稳定或使用明确回退色。
- `npm run test:all` 和静态检查通过。
