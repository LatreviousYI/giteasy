# 分支操作、自动 Fetch 与冲突区调整设计

## 目标

- 支持从远程分支右键创建本地分支，并允许修改默认名称、选择创建后是否切换。
- 支持本地分支右键拉取其追踪的远程分支。
- 支持删除本地分支时按需同时删除对应的远程分支。
- 将当前项目的自动 Fetch 默认间隔设为 60 分钟，并允许用户配置或关闭。
- 支持拖动调整冲突页版本区与合并结果区的高度比例。

## 非目标

- 不重构整个 Sidebar 或引入通用右键菜单框架。
- 不扫描或自动 Fetch 非当前激活项目。
- 不为没有上游的本地分支猜测远程分支。
- 不使用临时 worktree 为非当前分支执行 merge 或 rebase。
- 不改动发布流程或版本号。

## 交互设计

### 从远程分支创建本地分支

- 远程分支右键菜单增加“创建本地分支…”。
- 对话框默认名称为去掉已知远程名前缀的分支名。例如 `origin/feature/login` 默认填写 `feature/login`。
- 名称输入框允许用户修改。
- 对话框提供“创建成功后切换到该分支”，默认勾选。
- 同名本地分支已存在且勾选切换时，切换到现有分支并提示“分支已存在，已切换”。
- 同名本地分支已存在但未勾选切换时，不创建、不切换，并提示分支已存在。

### 拉取本地分支的追踪分支

- 本地分支右键菜单增加“拉取对应远程分支”。
- 当前分支存在有效上游时，直接进入现有自动 Pull 流程。
- 非当前分支存在有效上游时，先安全切换到该分支，再拉取。
- 菜单项只在存在有效上游时启用；没有上游时显示不可用原因。
- 切换失败、工作区冲突或存在不适合切换的改动时，展示 Git 错误，不强制切换或覆盖。
- 只有在切换成功后才允许执行 Pull。

### 删除本地分支及可选远程分支

- 删除确认框在本地分支存在有效上游时显示“同时删除对应的远程追踪分支”。
- 该选项默认不勾选。
- 确认框明确展示将删除的远程和远程分支。
- 用户在同一个后端命令中完成删除，命令持有仓库写锁。
- 顺序为先删除本地分支，再删除远程分支。
- 本地删除失败时不尝试远程删除。
- 本地删除成功但远程删除失败时，错误信息必须明确说明本地分支已经删除、远程分支未删除。

### 自动 Fetch

- 自动 Fetch 间隔默认值为 60 分钟。
- `0` 继续表示关闭。
- 用户已经明确保存为 `0` 的设置不被强制迁移。
- 只为当前激活项目安排计时；切换项目后重新为新的当前项目计时。
- Fetch 完成后刷新状态、历史和分支查询。
- 上一次 Fetch 完成后才安排下一次，避免慢网络下任务重叠。
- 自动 Fetch 失败不连续弹出重复 Toast。

### 冲突区高度调整

- 在版本区与合并结果区之间增加水平分割条。
- 支持鼠标和触控拖动，并支持键盘上下键调整。
- 版本区和结果区都设置最小高度。
- 调整后的比例写入本机 `localStorage`，下次打开冲突页继续使用。
- 只调整冲突页内部布局，不改变全局工作区布局。

## 代码边界

- `src/components/sidebar/SidebarSections.tsx` 继续负责菜单入口和展示，不承载 Git 业务逻辑。
- `src/components/Sidebar.tsx` 使用带 `scope: 'local' | 'remote'` 的菜单状态区分分支类型。
- 新增 `src/features/branches/`：
  - 远程分支创建对话框。
  - 带可选远程删除的确认对话框。
- `src/lib/remote.ts` 增加指定本地分支的安全切换和 Pull 编排。
- `src/lib/ipc.ts` 扩展删除本地分支调用，使其可携带可选远程信息。
- `src-tauri/src/write.rs` 扩展 `branch_delete`，在同一个仓库写锁内执行本地和可选远程删除。
- 自动 Fetch 保留在 App 级当前仓库逻辑中，调整默认值、调度方式和并发保护。
- 冲突页增加局部比例状态、上下限计算和分割条事件处理。

## 数据流

1. Sidebar 根据菜单对象类型展示本地分支或远程分支动作。
2. 对话框返回用户确认的分支名、是否切换或是否删除远程。
3. Sidebar 通过 `ipc.ts` 调用对应后端命令。
4. 后端命令通过共享 Git 执行层完成操作。
5. 成功后统一 invalidate 当前仓库查询；失败由统一错误标准化显示。
6. 自动 Fetch 读取保存的设置，在当前激活仓库路径变化时重建定时器。
7. 冲突页拖动只更新局部 UI 状态并持久化比例。

## 错误处理

- 没有上游的分支不显示可用 Pull 动作，并给出原因。
- 上游名称无法匹配已配置远程时，不提供远程删除或 Pull 动作。
- 分支切换失败时终止后续 Pull。
- Pull 分叉沿用现有策略对话框。
- 删除远程失败时返回包含部分完成状态的明确错误。
- 自动 Fetch 错误不阻塞界面，不吞掉当前用户主动操作的结果。
- 冲突区比例计算必须夹在上下限之间，避免窗口变小时内容不可见。

## 测试

### 前端

- 远程分支右键触发创建菜单。
- 创建对话框默认名称正确，名称可编辑，切换选项默认开启。
- 同名本地分支在勾选和未勾选切换时行为正确。
- 没有上游时“拉取对应远程分支”禁用并显示原因。
- 非当前分支先切换再 Pull；切换失败不 Pull。
- 删除确认框仅在存在有效上游时显示远程删除选项，且默认关闭。
- 自动 Fetch 默认值为 60，0 可关闭。
- 冲突区分割条支持拖动、键盘调整、上下限和持久化。

### Rust

- `branch_delete` 在没有远程参数时只删除本地分支。
- `branch_delete` 在提供远程参数时删除本地分支和远程分支。
- 删除失败时错误语义正确。
- 设置默认值为 60。
- 使用临时真实仓库和本地 bare remote 执行集成测试，不访问公网。

### 真实仓库验收

- 使用 `/home/kerwin/workspace/python/test_tree` 和其 `gitee` 远程验证远程删除流程。
- 创建并推送临时测试分支后，通过应用后端删除本地和远程分支。
- 验证完成后确认本地与远程临时分支均已清理，不影响现有分支。

## 验收标准

- 四项交互均可在应用内完成，不需要用户手工执行 Git 命令。
- 删除操作不会静默产生部分完成状态。
- 自动 Fetch 只影响当前激活项目，默认每 60 分钟执行一次。
- 冲突区可调整、可恢复且不会把两侧拖到不可用。
- `npm run test:all` 和 `git diff --check` 通过。
