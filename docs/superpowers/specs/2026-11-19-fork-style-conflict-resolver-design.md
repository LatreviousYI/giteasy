# Fork 风格三窗格冲突解决器设计

## 目标

- 冲突内容在文件上下文中解决，不再用独立块卡片重复展示。
- 上方同步展示 Theirs、可选 Base 和 Ours。
- 下方提供可编辑的完整合并结果。
- 多块冲突可以逐块操作，不会自动改变当前块。
- 每个文件维护独立撤销栈，可连续撤销块操作和手动编辑。
- 切换文件再返回时恢复该文件的当前块、结果内容和撤销历史。

## 非目标

- 不复制 Fork 的视觉外观和全部编辑器能力。
- 不实现 Redo。
- 不提供语法高亮编辑器的完整 IDE 能力。
- 不改变 Git 冲突文件解析和写回语义。
- 不移除外置 Merge 工具入口。

## 页面结构

- 左侧保留冲突文件列表，并显示每个文件的已解决块数量和总块数。
- 右侧顶部固定栏包含：
  - 文件路径。
  - 当前块位置，例如 `第 2/3 块`。
  - 上一块、下一块。
  - 显示/隐藏 Base。
  - 外部工具。
- 代码对照区：
  - 默认左侧 Theirs、右侧 Ours。
  - 开启 Base 后为 Theirs / Base / Ours 三列。
  - 每列显示行号。
  - 当前冲突块在原文件中高亮。
  - 切换当前块时，各代码列滚动到对应区域。
- 当前块操作栏：
  - 采用我的。
  - 采用对方。
  - 两者保留，顺序为 Ours 后 Theirs。
  - 全部采用我的 / 对方 / 两者保留。
  - 撤销上一步。
- 下方结果区：
  - 完整文件内容。
  - 可直接编辑。
  - 使用等宽字体和行号。
  - 不再单独显示冲突块卡片。

## 多块冲突

- 原始冲突块解析后分配稳定 ID。
- `第 N/M 块` 基于原始块总数，不因已解决块消失而重新编号。
- 上一块、下一块按原始顺序移动。
- 下一块优先跳到下一个未解决块。
- 采用当前块后不自动跳转。
- 已解决块在导航和进度中显示完成状态。
- 单块采用只替换结果内容中对应冲突区域。
- 全部采用仍作为快捷操作，但进入同一撤销历史。

## 结果缓冲区

- 每个冲突文件维护独立的结果缓冲区。
- 初次打开时内容为当前带冲突标记的工作区内容。
- 单块操作将对应标记区域替换为：
  - Ours 内容。
  - Theirs 内容。
  - Ours 后接 Theirs。
- 普通文件内容和未处理块保持不变。
- 手动编辑直接修改结果缓冲区。
- 只有点击“保存并标记已解决”时才写回工作区文件并暂存。
- 仍存在未解决块时禁用保存按钮。

## 撤销

- 每个文件维护独立撤销栈。
- 以下操作进入撤销历史：
  - 采用单块 Ours。
  - 采用单块 Theirs。
  - 单块两者保留。
  - 全部采用。
  - 手动编辑结果。
- 快照包含：
  - 结果内容。
  - 已解决块状态。
  - 当前块。
- 连续撤销可以恢复原始冲突标记。
- 切换文件后撤销栈保留；切回后继续使用。
- 文件解决成功或合并结束会清理该文件会话。
- 手动编辑按编辑过程分组：
  - 进入结果编辑器时开始一个编辑版本。
  - 连续输入共享同一撤销点。
  - 失焦、执行块操作或切换文件后结束该编辑版本。
- 在撤销后执行新操作会清空后续历史；本轮不提供 Redo。

## 块状态

- 块状态包括：
  - `unresolved`
  - `ours`
  - `theirs`
  - `both`
  - `custom`
- 手动修改仍保留冲突标记时保持未解决。
- 手动删除某块全部标记后，该块视为 custom/resolved。
- 空 Ours 或空 Theirs 是合法状态，不显示为解析失败。
- 二进制冲突不显示代码窗格，只保留外部工具和标记已解决。

## 状态生命周期

- 会话按仓库路径和文件路径隔离。
- 切换文件时先保存当前文件会话，再从目标文件会话恢复。
- 新出现或内容变化的冲突文件没有现有会话时重新初始化。
- 文件从冲突列表消失后删除会话。
- 切换仓库时清空所有冲突会话。
- 文件列表刷新不能覆盖用户已有结果缓冲区和撤销栈。

## 组件边界

- `ConflictsView.tsx` 负责仓库级文件列表、会话选择和继续/中止操作。
- `ConflictMergeEditor.tsx` 负责顶部导航、代码窗格、块操作和结果编辑器。
- `useConflictSessions.ts` 负责按文件保存结果、块状态、当前块和撤销栈。
- `conflict.ts` 保持解析和单块替换纯函数，并增加稳定块模型所需工具。
- 三窗格组件只消费会话数据和回调，不直接调用 IPC。

## 错误与保护

- 冲突标记损坏时保留原文并显示解析提示，不自动覆盖文件。
- 文件写入失败时保留结果缓冲区和撤销栈。
- 保存成功但暂存失败时明确说明文件已写入但未标记解决。
- 外部工具不可用时保留内嵌解决状态。
- 当前块不存在时回退到最近一个未解决块，再回退到第一块。

## 测试

### 纯函数

- 多块冲突生成稳定 ID。
- 单块 ours/theirs/both 只修改对应区域。
- 混合选择多个块。
- 全部采用和单块采用顺序正确。
- 空 ours/theirs、add/add 和 diff3 base。
- 手动删除标记后块状态转为 custom/resolved。
- 损坏标记不会被静默修改。

### 会话与撤销

- 连续撤销恢复每一步结果和当前块。
- 全部采用后连续撤销恢复每个原始块。
- 手动编辑按编辑过程生成一个撤销点。
- 文件 A/B 切换后分别恢复撤销栈。
- 文件解决或仓库切换后清理会话。
- 撤销后执行新操作会丢弃后续历史。

### 组件

- 当前块导航不会自动跳转。
- 下一块优先选择未解决块。
- Base 开关切换两列和三列。
- 未解决块存在时保存按钮禁用。
- 手动编辑、块操作、撤销和保存调用关系正确。

### E2E

- 使用现有三块冲突仓库打开冲突页。
- 验证三窗格、块导航、当前块高亮和结果更新。
- 采用第二块后第一、第三块保持不变。
- 连续撤销恢复操作前内容。
- 切换文件再返回仍可撤销。
- 全部块处理后保存并标记。

## 验收标准

- 冲突块在文件上下文中展示，不再依赖独立卡片。
- 多块冲突可以逐块 ours/theirs/both，且不自动跳转。
- 每个文件的连续撤销历史独立保留。
- 未全部处理时不会误标记文件已解决。
- 二进制冲突和外部工具路径不回归。
- `npm run test:all` 和静态检查通过。
