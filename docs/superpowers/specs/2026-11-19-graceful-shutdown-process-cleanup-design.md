# 关闭确认与进程清理设计

## 目标

- 用户关闭窗口时，GitEasy 必须退出主进程、WebKit 页面进程、网络进程和 AppImage 启动层。
- 有 Git 操作正在执行时，关闭前必须提示用户确认。
- 用户确认关闭后，中断正在执行的 Git 子进程并清理应用资源。
- 用户取消关闭后，应用和已有操作继续运行。

## 非目标

- 不关闭用户主动打开的外部编辑器或终端。
- 不终止用户通过“自定义命令”主动启动的独立外部进程。
- 不改变 Git 操作本身的冲突、认证或错误处理语义。
- 不引入系统级守护进程或常驻托盘进程。

## 操作跟踪

- `AppState` 增加原子 Git 操作计数器和“正在关闭”标记。
- 所有通过仓库写锁执行的操作统一计数。
- 操作计数使用 RAII 守卫：
  - 获取仓库写锁时增加。
  - 操作成功、失败、取消或提前返回时自动减少。
  - 不允许在命令路径中手工成对增加和减少。
- 当前需要覆盖 Fetch、Pull、Push、提交、分支修改、合并、冲突写入、Rebase、Stash、Worktree 和其他写锁操作。
- 普通只读查询不纳入关闭确认，但主进程退出时仍必须关闭。

## 关闭入口

- Tauri 的 `CloseRequested` 是唯一关闭判定入口。
- 自定义标题栏关闭按钮、`Alt+F4` 和窗口管理器关闭都必须经过该入口。
- 操作计数为 0 时：
  - 阻止默认关闭流程。
  - 执行统一清理。
  - 调用 `app.exit(0)`。
- 操作计数大于 0 时：
  - 阻止默认关闭流程。
  - 向前端发送一次 `app://close-requested` 事件。
  - 事件包含当前操作数量。
  - 同一时间只保留一个确认框。
- 正在关闭标记防止重复关闭请求产生多个退出或程序卡死。

## 关闭确认

- 前端监听 `app://close-requested`。
- 确认框显示检测到的操作数量，并说明关闭会中断这些 Git 操作。
- 取消：关闭确认框，不调用退出命令。
- 确认：调用后端 `app_exit`，进入统一退出流程。
- 如果确认框打开期间操作数量变化，下一次关闭请求重新读取最新数量。

## 资源清理

- 统一退出函数执行以下同步清理：
  - 清空 Git 仓库文件 watcher。
  - 清空仓库会话注册表。
  - 设置正在关闭标记。
  - 调用 Tauri `app.exit(0)`。
- WebKit 页面进程和网络进程由 Tauri/WebKitGTK 随主进程退出。
- AppImage 启动层必须在主程序退出后自动结束。
- 外部编辑器和终端属于独立用户进程，不纳入强制清理。

## Git 子进程

- Tokio Git 命令启用 `kill_on_drop`。
- Linux 上为 Git 子进程设置父进程死亡信号 `SIGTERM`：
  - 主进程正常退出时，运行中的 Git 子进程收到终止信号。
  - 避免 Fetch、Pull、Push 等命令在 GitEasy 退出后继续占用网络或锁文件。
- 读取命令和流式命令必须共享同一 Git command builder，保证清理行为一致。
- 不使用“杀死整个进程组”的方式，避免误杀启动 GitEasy 的终端或 IDE。

## 前端组件边界

- 关闭事件监听放在 App 级生命周期 Hook 中。
- 确认框复用现有 `ConfirmDialog`，不复制遮罩、Escape 和按钮逻辑。
- Tauri 调用只经过 `src/lib/ipc.ts`。
- 自定义窗口关闭按钮继续调用当前窗口的 `close()`，由后端统一处理，不直接强制退出。

## 错误处理

- 前端发送关闭事件失败时，后端不得默认强制退出；保留应用运行并记录错误。
- 清理过程中单个 watcher 或会话释放失败，不得阻止主进程退出。
- 用户确认退出后，重复关闭请求直接忽略。
- 操作计数只允许减到 0，不允许出现下溢。

## 测试

### Rust

- 操作计数器在成功和失败路径后恢复为 0。
- 并发仓库操作产生正确计数。
- 退出清理会清空 watcher 和仓库会话。
- 重复退出请求只执行一次。
- Git command builder 保持共享环境与子进程清理配置。

### 前端

- 收到关闭事件后显示带操作数量的确认框。
- 取消不会调用退出 IPC。
- 确认调用退出 IPC。
- 重复事件不会创建多个确认框。

### 真实进程验收

- 启动打包后的 AppImage。
- 确认存在 `giteasy`、WebKit 页面进程、WebKit 网络进程和 AppImage 启动层。
- 通过窗口关闭入口退出。
- 等待 3 秒后确认以上进程全部消失。
- 使用页面上可见的关闭按钮和 `Alt+F4` 两种路径分别验收。

## 验收标准

- 没有正在执行的操作时，关闭窗口立即退出。
- 有正在执行的操作时，关闭窗口先显示确认框。
- 取消后应用继续正常运行。
- 确认后不残留 GitEasy、WebKit 或 AppImage 相关进程。
- 不误杀外部编辑器、终端或启动 GitEasy 的父进程。
- `npm run test:all` 和 `git diff --check` 通过。
