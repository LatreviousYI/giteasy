## M0 架构加固与执行基线

### M0-01 RepoSession 与仓库注册表

- [x] 新增后端 RepoSession 注册表，以规范化路径作为 repoId。
- [x] 每个 session 持有独立写锁和生命周期状态。
- [x] 保持现有仓库打开流程兼容。
- [x] 测试：同一 repoId 返回同一 session；不同仓库得到不同 session。

验收：现有仓库可正常打开；session 可按路径查询；不同仓库 session 不共享写锁。

### M0-02 写操作串行化

- [x] 所有会修改 index、refs、工作区或临时操作状态的命令进入对应 RepoSession 写锁。
- [x] 只读操作不获取写锁。
- [x] 增加并发写测试，证明同仓库操作串行、不同仓库可并行。

验收：并发 stage/commit 不交错修改同一仓库；不同仓库写操作不被全局锁阻塞。

### M0-03 仓库关闭与 watcher 生命周期

- [x] 新增 `repo_close` 命令，释放 watcher 与 session。
- [x] closing 后再次 open 可恢复干净 session。
- [x] 前端关闭仓库和切换前调用关闭流程。
- [x] 测试 watcher 停止和资源移除。

验收：关闭仓库后 watcher 不再发送该仓库事件；重新打开后 watcher 正常工作。

### M0-04 ActivityLog 基础

- [x] 实现仓库级 ActivityEvent 模型和有限长度环形记录。
- [x] 写操作记录命令、开始/结束时间、结果摘要和 hooks/output。
- [x] 新增查询命令供前端 Activity 面板使用。
- [x] 错误详情脱敏，不记录 credentials 或 token。

验收：提交、fetch、错误和 hooks 输出可查询；关闭仓库后记录按既定策略保留或释放。

### M0-05 libgit2 读取阻塞隔离

- [x] 将当前同步执行 libgit2 的读取路径迁移到 Rust 阻塞线程池。
- [x] IPC DTO 与前端调用方式保持稳定。
- [x] 添加读取大仓库时不阻塞异步运行时的测试或可重复基准。

验收：读取命令异步执行；现有 8 个后端测试通过；前端无需感知线程模型变化。

### M0-06 前端 repoId 与状态边界

- [x] 查询键统一为 `[domain, repoId, ...params]`。
- [x] Store 中当前仓库、选中文件、diff、提交草稿按 repoId 隔离，为多 Tab 预留模型。
- [x] 不改动现有用户可见布局作为本任务目标。

验收：切换两个模拟 repoId 时状态不串；现有单仓库流程保持可用。

### M0-07 拆分巨型组件

- [x] 将 Sidebar 中的仓库菜单、分支、远程、Tag、Stash、Worktree、Submodule 拆成独立组件。
- [x] 将 Changes、History 的详情和提交区拆成可测试子组件。
- [x] 不改变现有行为，只调整边界。

验收：单文件行数显著下降；构建和现有流程通过；每个子组件职责单一。
